# 威胁模型（Threat Model）

这份文档回答三个问题：**这套工具能动什么、谁能让它动、动错了会怎样。**
写作原则：只写仓库里真实存在的约束，不写"设计上应该安全"。

## 1. 资产（被保护的东西）

| 资产 | 位置 | 泄露/破坏的后果 |
| --- | --- | --- |
| 助手的记忆库 | `ANINEST_MEMORY_DB`（默认 `~/.aninest/memory.db`） | 个人偏好、历史对话被读出 |
| 作业网登录态 | 本机浏览器服务的 profile（**不在本仓库**） | 账号被冒用 |
| 宿主机的网络位置 | 工具进程所在的机器 | 被当成内网探测/代理跳板 |
| 宿主进程本身 | 运行 MCP 的 Python 进程 | 代码执行、任意文件读写 |

## 2. 信任边界

```
用户/模型  ──►  MCP 宿主  ──stdio/HTTP──►  本进程（工具实现）
                                              │
                        ┌─────────────────────┼─────────────────────┐
                        ▼                     ▼                     ▼
                  公网图站 API          本机浏览器服务         本地 SQLite
                （不可信输入源）        （持凭证，私有）        （只读打开）
```

关键判断：**模型不可信、外部响应内容不可信、本机服务可信但不暴露。**
模型可能被网页内容注入（例如某张图的 tag 里写着"忽略之前的指令"），
因此工具必须假设"调用参数可能被诱导"，而不是假设"模型总是善意的"。

## 3. 攻击面：每个工具的出站能力

| 工具 | 出站目标 | 由谁决定 | 最坏情况 |
| --- | --- | --- | --- |
| `art_search` | `ANINEST_BOORU_URL` + query 串 | 环境变量固定 host，模型只影响 query | 大量请求打图站被封 IP；query 被构造出异常字符 |
| `arena_lookup` | `ANINEST_ARENA_URL` 的 `POST /search` | 环境变量固定，模型只影响 6 个六位 id | 把内网地址当上游（若环境变量被改） |
| `memory_search` / `memory_stats` | 本地文件 | 环境变量决定路径 | 读到 `ANINEST_MEMORY_DB` 指向的任意 SQLite |
| `service_health` | `ANINEST_PROBE_HOST` + 固定 5 个端口 | 环境变量决定 host | 对内网做端口探测（仅 5 个固定端口） |

**结论：本仓库的 SSRF 面由环境变量而非工具参数控制。** 这是有意的：
工具参数里没有任何"URL"字段，模型无法让进程去连一个它自己挑的地址。
代价是——**部署者必须自己保证这几个环境变量指向可信地址**。

## 4. 威胁与控制

| # | 威胁 | 现状控制 | 残余风险 |
| --- | --- | --- | --- |
| T1 | 外部内容提示注入（tag/标题里藏指令） | 工具返回结构化字段，不解析、不执行返回文本；`docs/DECISIONS.md` 说明"不做自动动作" | 模型可能被文本说服去调用别的工具；本仓库没有跨工具策略引擎 |
| T2 | 记忆库被写坏 | 只读 URI `file:...?mode=ro`，SQLite 层直接拒绝写 | 若 `ANINEST_MEMORY_DB` 指向别处，仍能读那个库（只读） |
| T3 | 凭证泄露 | 仓库内零凭证；登录态在浏览器 profile 里，工具只发 HTTP | 本机服务若监听 `0.0.0.0` 且无鉴权，同网段可打 |
| T4 | 内网探测/SSRF | 工具无 URL 参数；`arena`/`art` 的 host 来自环境变量；`service_health` 只探固定 5 端口 | 部署者把 `ANINEST_PROBE_HOST` 指向内网即可扫那 5 个端口 |
| T5 | 资源耗尽（请求风暴、超大响应） | 单请求超时（默认 15s）、降级阶梯最多 3–4 次请求、`limit`/`count` 有上限、返回只保留必要字段 | 没有跨调用的速率限制；高频调用仍会打满出网带宽 |
| T6 | 返回内容过大撑爆上下文 | `art_search` 只回 URL 与元数据（不回图片字节）；`memory_search` 默认 5 条、上限 20 | 图站返回的超长 tag 列表会原样透传 |
| T7 | 假数据/幻觉 | 网络错误、非 JSON、空结果分别抛 `ToolError`；返回里带 `relaxed`/`attempt` 说明是否降级 | 上游本身返回错误数据时无法识别 |
| T8 | 供应链 | 依赖锁定 `mcp>=1.20,<2`、`httpx`；CI 只跑离线评测 | 未做依赖哈希锁定（no lockfile with hashes） |

## 5. 明确不防御的范围

- **宿主被攻破**：如果运行 MCP 的进程本身被拿下，工具内的所有约束都失效。
- **模型被越狱**：工具不做"这次调用是否合规"的判断，那是宿主的权限系统该做的事。
- **用户主动作恶**：部署者能改环境变量，就能让工具连别的地方——这属于部署决策，不属于代码缺陷。
- **多租户隔离**：本服务假设"一个用户、一台机器"，没有租户概念。

## 6. 部署建议（给要跑它的人）

1. 用**只读**方式挂载记忆库目录，或直接指向一个副本。
2. `ANINEST_ARENA_URL` 只填 `127.0.0.1`；本机浏览器服务不要监听 `0.0.0.0`。
3. 需要给多人用时，前面加一层网关做鉴权与限速；本项目自带的 HTTP 模式**没有鉴权**。
4. 出网策略：只放行图站域名；`service_health` 的 host 固定为 `127.0.0.1`。
5. 定期看工具返回里的 `relaxed`/`attempt` 字段——异常升高往往意味着上游变了或被限流。

## 7. 已知缺口（写在这里，而不是等 reviewer 发现）

- 无跨调用速率限制（只有单请求超时）。
- 无出网白名单的代码级强制（只靠环境变量约定）。
- `service_health` 的端口列表写死在 `config.py:SERVICES`，改端口需要改代码。
- 日志默认打到 stderr，没有脱敏层；若上游 URL 带 query 会被原样记录。
